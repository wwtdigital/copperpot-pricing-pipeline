# Copperpot Bowls: copperpot-pricing-pipeline

> **Fictional company.** Copperpot Bowls is a fictional company. This repository, its history and its data were generated by WWT Digital to demonstrate the Agentic Readiness Scorecard. No real company, person or system is behind it.

Copperpot Bowls pricing pipeline: menu items, store pricing tiers, promotions and the daily price book the commerce API reads, as dbt models on DuckDB with a publisher script. Fictional demonstration estate.

---

## What this is

The pricing pipeline: dbt models on DuckDB that turn the menu, the store list, the pricing tiers and the promotion calendar into a daily price book, one row per store, item and day. The commerce API reads the price book; nothing here serves traffic.

| Layer | Models | Grain |
|---|---|---|
| seeds | `stores`, `menu_items`, `pricing_tiers`, `promotions`, `price_calendar` | the inputs, as CSV |
| staging (`models/staging/`) | `stg_*`, one view per seed | one row per source row, typed and renamed |
| marts (`models/marts/pricing/`) | `dim_stores`, `dim_menu_items`, `store_item_prices`, `promotion_windows`, `price_book_daily` | store, item, store by item, promotion by day, store by item by day |

## Running it

Python 3.13 or newer. With [uv](https://docs.astral.sh/uv/):

```shell
uv sync
uv run dbt seed
uv run dbt run
uv run dbt test
```

Or with a plain virtual environment and the pinned requirements:

```shell
python3 -m venv .venv
source .venv/bin/activate
python3 -m pip install -r requirements.txt
dbt build
```

`dbt build` does seed, run and test in one pass. The database is a local file, `copperpot_pricing.duckdb`, ignored by git; delete it to start over. Query it with the DuckDB CLI:

```
select * from price_book_daily where store_id = 106 and price_date = '2024-09-16';
```

## Linting

SQL style is checked with sqlfluff (`.sqlfluff` carries the rules):

```shell
uv run sqlfluff lint models
uv run sqlfluff fix models
```

## Checks

Every change runs `.github/workflows/ci.yml`: `uv sync --locked`, `dbt build` against a fresh DuckDB file, `sqlfluff lint models`. The same three commands are the local loop. Dependency updates for pip arrive weekly from dependabot.

## Publishing the price book

`scripts/publish_price_book.py` cuts one JSON document per price date from `price_book_daily`:

```shell
uv run python scripts/publish_price_book.py --date 2024-09-16 --out out
```

The store systems promotion tooling runs it from a release tag and uploads the file for the commerce API. See `docs/model-guide.md` for the models and what the tests cover.

## Tests

dbt tests run inside `dbt build`. The publisher's cases run with pytest:

```shell
uv run pytest
```
